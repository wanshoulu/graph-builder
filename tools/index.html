01这是什么

graph-builder 是一套 Node.js 原生 http 服务 + 独立前端组成的图谱构建与进化工具链。前半段解决「建库」：把业务人员填报的 Excel、docx/pdf 文档、CSV/JSON 表格、Agent 对话描述、内置种子数据、v2.1 存量图谱这六类原料，统一加工成一张属性图，并在每次写入时强制校验；后半段解决「改好」：用意图识别的错题驱动 RSI 闭环，产出可验证、可回滚的图谱版本。

名词含义
知识图谱由节点（实体/概念/功能）与边（关系）构成的有向属性图，用来把业务知识预定义成结构化数据。
模板一份 JSON，同时声明节点/边类型、字段契约、枚举、条件必填规则和种子图。校验规则写在模板里，不写死在代码中。
草稿当前正在编辑的图谱文档，保存在 data/graphs/org/<asset>/drafts/。任何写入都先落到草稿。
资产（asset）一张具名图谱，由 data/graph-assets-registry.json 注册，绑定一张模板。
摄入批次一次 Excel 导入产生的候选行集合，经逐行评审、预检、应用后才合入草稿。
发布版本草稿通过校验后生成的只读版本，形成 v1→v2→… 版本链，可回滚。
RSIRecursive Self-Improvement（递归自我改进），出自 openJiuwen 2026 年 9 月发布的双维度 RSI 框架（Harness 优化 + Artifacts 优化）。本仓库是这套思路在「意图图谱」上的落地实现。

02六条建图入口，一道校验门

原料形态机制入口
Excel 填报摄入审核流（人在环上）POST /api/knowledge-intake/import
docx / pdf / txt / md文档抽取 + 块级进度 + 断点续跑/api/org-graph/parse-document → extract
CSV / JSON 表格表头确定性映射（零 LLM、可复现）POST /api/org-graph/from-tabular
自然语言Agent 对话建图/api/org-graph/builder-agent/*
内置种子数据一键起步POST /api/org-graph/seed
v2.1 存量图谱importer 注册表双通道迁移POST /api/org-graph/import

六条路径共用同一个三段校验管线：骨架（ID 唯一 / 类型白名单 / 无孤儿边 / 无自环）→ 字段（必填 / 类型 / 枚举 / 禁止模板外字段）→ 条件必填（跨字段约束由模板声明）。服务端在 apply 时强制阻断 valid:false，不信任前端。

03RSI 意图进化：Agent + Skill 闭环

前半段把图谱建出来，后半段要回答「这张图识别意图准不准、怎么改」。RSI 闭环拿意图识别的错题当反馈，生成改进提案，用同一套评测引擎复测，只采纳有净收益且过门禁的改动，形成可回滚的版本链。

名词含义
V2 架构services/rsi-agent/ 是独立 Python 进程：openjiuwen 0.1.19 的 create_deep_agent + 两份 SKILL.prompt 作 system_prompt + 5 个 HTTP 工具。Node 侧 routes/intent-rsi.js 不是推理主体，它负责调度、状态持久化、测量与采纳门禁。
Skill放在 skills/{proposal,attribution}/SKILL.prompt 的提案/归因指令。扩展名必须是 .prompt——openjiuwen.harness 按扩展名注册 parser 接管 .md 读取；另有 app/skill_texts.py 把正文烧录进镜像，规避 WSL2 bind mount 视图陈旧。
决策模式rules（V1，Node 内规则+LLM）／model／agent（V2，Python Agent 走 /v1/tasks/propose）。
工具桥/api/intent-rsi/agent/* 五个端点（weaknesses / badcases / search / intent / probe）供 Agent 读 Node 状态；probe_query 把草案真应用到引擎做反事实复测，闭环保证来自工具反馈而非 prompt 纪律。
测量门禁四关：练习题初筛 → 防回退 → 隐藏考 → 生产引擎复核。成绩带引擎指纹，跨指纹不可比；模型/召回通道降级时整次测量作废，不产生结论。

两套前端都在仓库里：V2 工作台（React SPA）覆盖任务管理、自动进化、候选对比、资产谱系与成绩轨迹；V1 实验台是单文件页面，适合直接看 /state、/baseline、/propose 的原始响应。

V2 的 Agent 是独立进程（services/rsi-agent，默认 :18132），需按 requirements.txt 安装 openjiuwen 等依赖并配置模型密钥后启动。不启动它，Node 侧仍可用 rules/model 模式，V2 工作台的状态与历史也能查看，但 agent 决策模式不可用。

05模板生态

仓库内置 14 张模板（data/graph-builder-templates/），覆盖意图图谱、组织人力、客户风控、领域知识与通用底座五类；其中 template.intent.v2.json 同时是 RSI 评测引擎的 schema 基准。新增一张图谱 = 一份模板 JSON + 注册表一行，校验/草稿/版本/发布/审计全部复用，零代码。

06快速开始

npm install
npm start          # 默认 http://127.0.0.1:3013 → /tools/index.html
                   # RSI V2 工作台 /intent-rsi  ·  V1 实验台 /tools/intent-rsi-lab.html

# 可选：启动 Python Agent（agent 决策模式才需要）
cd services/rsi-agent && pip install -r requirements.txt
RSI_AGENT_API_BASE_URL=http://127.0.0.1:3013/api/intent-rsi/agent \
  uvicorn app.main:app --port 18132

改端口：PORT=4013 npm start。跑测试：npm test（全量，含继承的 RSI 历史失败）；全绿门禁：npm run test:core；只看 RSI：npm run test:rsi，口径见 README「测试口径」。

服务默认绑定 127.0.0.1 且 SKIP_AUTH=true（免鉴权）。这是为了本机开箱即用：若需对外提供，务必设置 SKIP_AUTH=false + JWT_SECRET，并在反向代理层做认证与访问控制。

07已知限制

  • 本仓库只带 14 张模板、样例 CSV、一个种子草稿、RSI 的 3 份种子数据和一份演示图谱；AI Harbor 中 29 MB 级存量图谱、RSI 的 1186 个运行期文件（checkpoints 2.0 GB、artifacts 388 MB 等）未随仓上传，编辑器版本列表与进化历史初始为空属预期。
  • AI 辅助（映射、抽取、扩问、节点审核、自动建图 generate）需要 .env 中配置 DEEPSEEK_KEY/QWEN_KEY 等密钥；未配置时这些端点返回明确错误，离线能力照常可用。
  • 无模型密钥时 RSI 评分子进程仍能跑完打分，但 /baseline 会因召回通道降级被测量门禁拒绝（HTTP 400）「本次测量不作为收益证据」——这是设计行为，不是故障。
  • Python Agent 需 openjiuwen==0.1.19 等依赖（本机未安装），agent 决策模式与 /agent/* 工具桥须先启动该服务；无运行中 Agent 代次时 /api/intent-rsi/agent/weaknesses 返回 500 属预期降级。
  • RSI 的 18 个 Node 测试继承源仓 13 个既有失败：运行时新增了「rules 模式必须注入 propose 服务」的早期校验，而测试 fixture 仍传 propose: undefined；源仓与独立仓失败名单完全一致，非本次剥离引入。
  • web/dist 是从单体带来的预构建产物，API 前缀仍是 /ontomind/wiki/api，由 server.js 兼容层归一化到 /api；web/src 源码已改为 /api，改源码后需自行 npm run build 重建 dist。
  • /api/org-graph/builder-agent/*、/trial-agent/* 默认指向外部 Agent 服务（BUILDER_AGENT_URL、TRIAL_AGENT_URL），独立部署时若未启动该服务，这两组端点不可用。
  • 原单体中依赖「知识产品平台 / Knowledge Builder Runtime」的 x6-graph-builder.html 及 /api/knowledge-builder/* 未纳入本仓库——它们的后端路由依赖十余个运行时模块，剥离后会留下大量 404。
  • 单文件 HTML 应用不提供打包、路由或权限模型；发布、回滚等写操作无二次确认以外的服务端保护，请勿在共享环境直接暴露。
