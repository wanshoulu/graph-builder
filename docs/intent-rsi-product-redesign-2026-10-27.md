# RSI 产品工作台重设计 · 2026-10-27

2026-10-30 用户补充：具体任务需要以对话式实时进展为中心，右侧常驻任务配置、代际版本指标、精度趋势及其他指标。本轮将其作为新的明确设计要求实施；原有按页签排列的方案不作为该要求的完成状态。

## 对上一轮交付的纠正

上一轮主要完成信息折叠、导航排序与加载优化，没有进行产品竞品对照，也没有重建任务对象及操作关系。不能称为完整产品设计。本轮将算法调研与产品调研分开，以下来源是官方流程/截图研究，不冒称使用过它们的付费或登录后产品，也没有用户访谈与真实用户可用性测试。

## 任务、对象与闭环

目标用户：需要为识别效果负责、能够审阅改动与证据的业务/算法人员。日常任务是“找出值得修的问题，尝试有依据的修改，确认是否改善，再决定采纳”。系统任务包含四种相互关联的对象：题目及证据、运行及实验、候选资产、正式版本。封存终测独立于优化过程。

完整路径：准备题目与目标 → 当前版本测量 → 定位失败及证据 → 运行实验 → 比较候选和回退 → 采纳至实验版本 → 独立验收与交付。

页面必须始终说明：所处阶段、当前对象、证据是否有效、这次操作会改变什么。保存的历史分数、当前版本有效分数、候选试验分数、封存终测分数不能互相替代。

## 布局方案比较

1. 继续使用长页与折叠：成本低，但对象与操作关系不变，不能解决此次问题，放弃。
2. 每步全屏向导：适合首次创建，反复跳转检查历史不方便，也不适合后台长任务，保留用于配置而不作为日常工作台。
3. **任务工作台 + 对象列表/证据检查面板 + 明确对比**：适合重复实验与审阅；需要重新组织数据展示与跳转。本轮采用，继续使用现有 React/AntD 和 API，保证旧 URL 与真实操作兼容。

## 页面职责与操作设计

### 1. 总览

- 持续可见的任务阶段：题目就绪、当前测量、实验运行、方案决策、独立验收；点击进入对应工作区。
- 当前有效精度与目标、历史参考和独立验收分开显示。当前失效则明确说明需重测及原因。
- 精度趋势直接可见；趋势、业务表现、代际谱系作为图表工作区切换，不把整套分析默认藏进折叠。
- 最近运行用结构化列表展示：优化对象、完成测量/候选数、验证变化、保留情况与详情入口。累计活动作为任务事实，不冒称有效收益。
- 决策面板明确显示当前阻塞与下一步，并进入对应工作区。

### 2. 问题定位

- 左侧可搜索/筛选的题目队列，右侧显示选中题目的期望、实际、评分与保存的召回/裁决证据。
- 数据来源、当前有效性、训练/验证范围和封存题数量始终可见。
- 无阶段证据时显示未记录；没有错误或只有历史测量时解释事实，不能捏造根因或失败计数。
- 选中题目可进入关联方案审阅，按真实 evidence/fixed case ID 匹配；没有关联方案时明确为空，不自动声称已安排定向优化。

### 3. 实验中心

- 保留运行列表及单次实验工作区，增加明确的并列比较入口。
- 允许选择基线与待比较运行；显示相同指标的运行前/保留结果、评测完成数量、对象、时长与采纳。
- 对缺失或不同数据/引擎条件显示不可直接比较；历史记录缺失不补造逐题改善/费用。
- 单次运行中的实验结果、归因、谱系是同一运行的不同视图，精确 URL 定位。

### 4. 方案决策

- 默认待决策，已采纳、未通过、已拒绝和全部历史各有筛选，防止历史卡片淹没当前工作。
- 列表选中后，固定检查区展示具体修改、来源、训练/验证结果、检查限制与后续操作。
- 父资产变化、评测过期、引擎复核与采纳资格依据现有真实契约；阻塞原因紧邻操作，不能以旧分数解锁。
- 支持两个候选并列比较与父子资产/逐题差异，保留拒绝、复测、重新生成和采纳实际入口。
- 来自题目定位的筛选条件可见、可清除；关联运行能直接跳转。

### 5. 验收交付与设置

- 验收页围绕当前版本有效性、终测、版本变更、导出组织，保持实验副本与线上发布的边界。
- 题库管理、运行偏好和维护放在设置及明确入口，不作为用户阅读结果的前置学习任务。
- 本轮不运行模型、采纳、终测或破坏性维护来演示页面，不制造新的精度收益。

## 验证标准

- 用真实 legacy-bank 任务渲染；缺少/失效/失败/空状态能解释清楚。
- 从总览进入具体运行；从题目进入证据与关联方案；从候选回到来源运行；取消筛选能回到完整队列。
- 默认页面有可读趋势和实际对象，不以继续增加折叠完成交付。
- 对比不能将未知计为零、将不同条件直接相减，或以成功状态推断未知费用/逐题改善。
- 所有旧 section 参数保留；完整既有引擎/资产分析、DAG、题型、业务指标和后台任务操作可达。
- 类型检查、关键模型/组件测试与 17386 浏览器流程通过；检查桌面/手机截图与键盘可达性。代码测试不等于真实用户已验证易用性。

## 实际实现与证据（2026-10-28 集成）

- `RsiTaskOverview`：默认可见十次历史实测与当前失效边界，趋势/业务/谱系/版本为明确的分析视图，最近运行直接打开精确 runId。
- `RsiFailureWorkbench`：真实题目队列、历史/当前来源、选中题目检查面板、已保存召回与裁决阶段、关联候选筛选。列表和详情分别进行请求失效保护；任务引擎/题集/切分/有效性变化会重新取证。
- `RsiCandidatesTable`：待决策/已采纳/未通过/已拒绝/全部历史队列，候选检查面板，两候选比较与父子差异。采纳、拒绝、生成、复核动作集中显示，移除原卡片对同一证据和阻塞的重复叙述。
- `RsiExperimentComparison`：明确选择参照和待比较运行，比较保留结果与执行情况。跨运行的条件一致还不足以放行：每次运行内部也必须有完整一致的评测证据。
- `RsiDeliveryWorkspace`：当前测量、独立验收、资产交接和版本档案。终测复用显示检查版本、资产、题集/切分和引擎，缺少证据时不认定当前有效；当前基线失效时禁用正式终测，与服务端要求一致。
- 主壳保持旧 URL section/runId 兼容，恢复设置为明确工作区，问题与候选用真实 case ID 关联，返回运行通过精确 runId。

本轮浏览器复核发现并修复历史 `targetName` 为对象时的崩溃，以及仅按版本/时间刷新导致证据失效后未更新的问题。前者有真实任务复现和组件回归，后者有独立只读浏览器模拟，二者证据分开保存。

## 尚未声称完成的部分

跨运行比较目前是保存的运行保留结果比较；不补造旧档案缺失的逐题差异、全链路费用或因果归因。逐题证据在问题工作区和具体实验中查看。本轮没有新增后台定向搜索算法，没有运行真实精度提升实验，也没有开展真实用户访谈/可用性试验。启动向导保留现有两步执行契约，高级配置和策略记忆文案仍有继续整理空间。
